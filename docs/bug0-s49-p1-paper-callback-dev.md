# Bug-0 P1 — real Paper callback ticks, one DEV World

This is the first developer experiment to bind original S49 ATTACK→REST
to a server-side monotone Bukkit tick callback timeline. Earlier #733 ran
only *invented* P1 tick numbers, so no real-tick model result could be
claimed there.

This exact commit explicitly authorizes one disposable Paper 1.21.8
World, a single original S49 ATTACK and later REST observation. The
source-only Java plugin is disabled by default and installed into this
one isolated DEV server under an explicit environment gate. No new Self
Action, no second Attack on UNKNOWN, no direct FatigueState writes into
runtime, and no learning, memory or energy credit.

The original P1 evaluator is **not merged or copied into this branch**:
the workflow checks out exact owner HEAD
`0ab76b4e46efd914877e543a65de58b6cfc71326`, checks its actual
Python module path and evaluates a read-only virtual P1 transition from
real Paper callback World-tick numbers. Paper source rows record a
tagged-target damage event and consecutive, bounded player motion,
swing, combat, damage and pose sampling across the post-REST interval.

Physical/epistemic ceiling: a plugin scheduler callback is not a
complete independently certified native packet/all-source whole-tick
activity census. Hence a P1 model decrease on these candidate ticks
is a DEV **virtual-body calculation using real server tick inputs**,
not an observed Minecraft Fatigue sensor or R-qualified recovery.

The evidence bundle must include original Paper server log, original
S49 report, read-only original P1 transition output and SHA256 manifest;
UNKNOWN or failure is retained and never auto-replayed. No changes to
P1/M/WB/R branches or protected main.
