# RelaySelf Cognitive v0.1 — Self-accepted Schema Presets and finite L1 exposure

Status: **OPT-IN CPU/OFFLINE DEV / PRESERVES NATIVE PARAMETERIZED HOLD**. Stacked on Draft #912 → #882 → #844. #828 / #829 / #843 are architectural references; #860 checkpoint stack remains independent.

## How Self accepts a new parameter configuration

- `SkillParameterPreset` is immutable, with explicit Pattern ID, named preset/version, Goal-independent Definition ABI digest, finite Constraints, requested `SkillBudget`, optional `SkillCostEstimate`, and provenance. The cost estimate is a fallible Self prediction; it does not bound WorldBody permission.
- `PresetAcceptanceReceipt(self_id, event_id, preset_ref, provenance)` represents the **existing Self owner's** acceptance. It is deliberately not a cryptographic proof. `accept_skill_parameter_preset` additionally requires `accepted_by_self=True`, the exact current `PatternRegistry.revision` (CAS), registered Goal Pattern, matching Skill definition/version/typed ABI and externally available Skill identity. An L2 proposal without Self acceptance cannot publish.
- Accepted records now live in `PatternRegistry.accepted_presets`, with the original Pattern revision, Self identity, immutable Preset and acceptance receipt. Up to 64 accepted live entries; publication is a **new** immutable registry snapshot, never an in-place mutation. Revisions for an existing (Self, Pattern ID, Preset ID) advance **exactly one**. Independent named Presets for the same Pattern coexist. `retire_skill_parameter_preset` removes future eligibility under an owner CAS; already issued physical Actions and their WAL are not erased.
- The existing `accept_learned_pattern` now carries accepted Presets into the next atomic registry snapshot rather than discarding them. The caller must still durably record acceptance events and persist/restore the registry through the existing cognition checkpoint owner. This pure code has **not** implemented or authenticated that owner ledger.

## Normal CURRENT Schema and SystemOne

With `cpu_schema_epoch(..., skill_definitions=..., use_registered_presets=True)`, Schema expands only already accepted Presets for the active Self. It creates a complete `SkillInvocation` **before** numbered SystemOne SELECT. No definition, no accepted Preset, invalid Target, wrong Self or Pattern revision => no executable option; the Goal/Need can remain unresolved, and L1 retains `ESCALATE_L2` and `DEFER`.

- Unlike the legacy branch's first-eight stop, this explicit mode enumerates a bounded eligible set (maximum 64 accepted Presets × 16 Percept Targets = 1024). Each option contains the exact Skill, Goal, Target, constraints, Budget and immutable preset digest. `Option.target_source_family` retains observation provider identity. The parameter/proposal provenance is stable across normal native probe sequence increments, while `SchemaFrame.source` keeps the latest live observation provenance.
- A CPU shortlist of **at most 8 physical options** is shown to L1. Emergency Goals receive priority. In the absence of an **explicit FAST crisis admission**, one exploration candidate is reserved when source-eligible, to avoid perpetual exploration starvation; the mere appearance of a Zombie is not itself this strong crisis mask. Under an explicit `fast_crisis=True`, exploration is excluded from eligibility, but its Goal is not erased. Round-robin by active Goal across epochs and by Target/Preset within a Goal; at most two different Presets for one Goal+Target appear in one round. L1 still chooses the actual option number; this reducer grants no action.
- `SchemaFrame.eligible_options` retains the full source-qualified membership for revalidation, distinct from display-only `SchemaFrame.options`. A new epoch rotating the presentation list **does not** itself invalidate an otherwise still-eligible selection; loss of target, source-family change, newer Preset, changed Constraints/Budget, changed World/Self or explicit crisis mask **does** reject. Native ActionPort rechecks live Target/currentness independently.
- Existing unparameterized callers still execute the legacy first-eight path; opt-in makes migration incremental. `experiments/cognitive_minimal_minecraft_dev.execute_one_cognitive_world_turn(..., use_registered_presets=True)` now uses this path for both original and refreshed native Schema frames and returns `INVOCATION_BOUND_NO_ISSUE` after a number-only L1 selection and fresh correlated probe. In this mode `issue_native=True` is rejected *before native IO*; legacy EAT/ATTACK and MOVE physical issuers **cannot** receive new parameterized calls. The CLI does not expose a new production/live native issuer.

## Negative tests / limitations

Tests cover missing acceptance, CAS conflicts, stale / duplicate owner event, monotonic version, foreign Skill ABI / wrong Self, zero physical grants, revocation, old snapshot preservation, learned Pattern coexistence, emergency inserted after a flood, exploration presence in noncrisis, explicit crisis suppression, 42 competing Goal exposure under an 8-option ceiling, multiple Presets for one Goal+Target, source change vs normal probe refresh and presentation-only rotation after L1, and the real one-turn function driven by a **fake** Mineflayer protocol with no native Action.

**Nonclaims:** This is not an authenticated Self owner decision service, persisted journal or checkpoint-recovery flow; not a physical parameterized ActionPort budget/constraint admission; not measured real SystemOne/Gemma throughput, real Paper/Minecraft action causality, QUAL or SCIENCE. Original unresolved `PREPARED_UNRESOLVED` MOVE WAL is neither examined nor replayed. Ranking/exposure is a CPU DEV candidate policy, not an assertion of better learned intelligence or safety.
