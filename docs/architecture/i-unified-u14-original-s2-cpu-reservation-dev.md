## What is now connected (scoped synthetic CPU only)

The **same original** `PhysicalIssueAdmission` implements `original_i4a_s2_first_wal_window`, `require_original_i4a_s2_wal_window` and `consume_original_i4a_s2_action_once`. It holds the original `owner.cohort.lock → physical gate lock` for a synchronous, typed `I4AS2EmptyRunBoundary` recheck; acquires the original per-Self MOVE_PLACE lease; and preconsumes the **new original parent Action ID** before durable WAL CAS. A failed CAS does not return the consumed ID. `ExitStack` can retain the same lease only; no new issuer, selector, native child ID, WAL owner or replay authority is introduced. Unbound original PLACE children remain rejected by the existing `submit_native_effect` path.

The common `begin_physical_issue_dev` now accepts a **fully matched** original `i4a_s2_boundary/owner/physical` tuple and `allow_prior_original_place_terminals=True` only **inside that original issue window** after one-use consumption. It rechecks the original Owner's Intent, Skill, Supervisor, canonical journal and Native current probe, exact old prefix count/SHA/action IDs, all old `NATIVE_PLACE_MOVE_SETTLED` and old `OUTCOME` identities, and a genuinely new Action against the prior terminal prefix. It then uses the existing original WAL v2 `prepare_place_move` **before** the same Supervisor `ISSUE`. Missing/partial S2 parameters or a prior-history exception outside this window are denied before mutation. EAT/ATTACK/ordinary MOVE and first PLACE paths retain their prior no-history restrictions.

The older `reserve_s2_first_original_move_synthetic_dev` declares the special prior-history mode explicitly. Its `require_i4a_offline_scripted_native` **continues to reject any real process-backed Native session**, including a subclass carrying hidden process resources. The U11 diagnostic reports that the **CPU signatures** are present but still has `real_world_authorized=False` and `independent_source_authenticated=False`.
