## Scope

This increment only bridges the previously divergent semantics:

- The #882 cognitive prototype has `DESTINATION` targets and an external `exploration_need` flag. A destination has geometry and potentially an arrival envelope.
- The #914 physical issuer has only `RELATIVE` native controls (`forward/back/left/right`) and a bounded pulse. It cannot infer a reachable place or guarantee arrival.
- This Stage24a version creates an opt-in `EXPLORE_WORLD → MOVE@1 → RELATIVE` innate Schema pair, feeding the **existing** `cpu_schema_epoch → assemble_l1_select → resolve_l1_choice` pipeline. Default initial patterns and old destination experiments are not replaced.

The new `resident_l1_move_options_dev.py` projects the **native probe** into a *conservative* low-pressure exploration opportunity, when the existing Intent owner is idle, health ≥16, food ≥18, known oxygen >0, time observed, nearby entity coverage untruncated, and no entity presently observed. Its trigger is computed by CPU from WorldBody/owner evidence, **not an operator-supplied GO/MOVE flag**. This simple innate drive is a DEV heuristic and does not establish genuine curiosity, obstacle-free ground or safety.

The available relative controls are native Action catalogue refs, not observed destinations. The module builds four distinct `Goal + Skill@version + relative control + pulse=0.35s` prebound options, plus `ESCALATE_L2` and `DEFER`, with exact choice numbers. A candidate-set SHA256 includes Self/native session, observation source/request/seq, and frozen preset parameters. Model output may select only one presented number. No direction/pulse/distance or tolerance is generated by L1.

On a *new* native probe, selected dependencies are checked against a fresh CPU Schema/Owner frame. Unrelated epoch changes do not invalidate the choice; food/oxygen/coverage changes, new nearby threats, missing physical capability or another World session reject it. An accepted selection can form one original `PhysicalActionBinding` through `propose_bound_physical_action` using the existing committed Intent and started SkillExecution, but the receipt stays `PROPOSED_NOT_AUTHORIZED`.

**No native Action is issued by this module.** No existing Stage23b owner, fsynced WAL, native STOP, Paper or checkpoint is changed. The postselection proposal uses one refreshed probe for typed binding, not a Stage23b physical issue grant; Stage24b must obtain the exact required two fresh native post-L1 probes and revalidate original issuer admission before an actual MOVE. The earlier #914 operator choice remains unchanged.
