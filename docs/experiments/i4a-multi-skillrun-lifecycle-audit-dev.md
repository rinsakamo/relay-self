# I4a: multi-SkillRun lifecycle audit (HOLD)

Base: C #1060 at ec3922a9e6727a8a59cdfde3df1d308c128ba2f1. I1 #1062 was read at c9a2b19e9fab0aa2ecd035ec2313d8e20ce3dffb; it is an independent branch, not incorporated here. This is an investigation and a negative characterization test, not an implementation or integration PASS.

Issue #828 §27.B explicitly does not abolish multiple Intents or SkillRuns. The following restrictions instead belong to bounded Stage26/27 experimental paths. They are safety gates and must not simply be deleted:

* `prepare_restored_preset_l1` requires equality with the restored retained snapshot and creates a separate empty IntentCommitment for its L1 round. `finish_restored_preset_l1` rechecks that old retained snapshot. A newly retained Memory therefore prevents the next selection. The demo target reference and selected registered preset are not independently minted for a new run.
* `begin_stage27_owned_move_intent` rejects any `owner.skills` history even if the previous Skill was explicitly terminated and the current Intent explicitly released. The Owner provides `finish_reviewed_skill` and `complete_intent`; the former requires explicit review and adoption, and neither a settled Action nor an evaluation automatically implies Skill or Goal success. Completing an Intent must not be used to claim an unmet Goal was completed.
* `Stage27hBoundedMoveLoop` compares its current action count and current budget against the whole canonical WAL; the original issuer's `begin_physical_issue_dev` also requires all supervisor actions and WAL rows to belong to the same Skill and Invocation. The default issuer rejects any previous supervisor action. A per-run boundary must preserve full-journal validation, unresolved-action fencing, source ordering, unique identity, and proof that the prior prefix is unchanged across reservation and settlement.
* `c_lane_stage27hi_multi_action_review_dev` and `c_lane_stage27_source_bridge` also require the entire WAL to equal the current Action cohort. They must authenticate a current-run range while still checking the complete canonical WAL and digest. Simply slicing rows supplied by a caller would weaken the evidence boundary.
* Stage28 checkpoint captures typed Owner/Intent/Skill and canonical WAL; restore does not reconstruct a process-local Stage27h parent, nor authorize old Skill resumption or a new Action. A new boundary must not manufacture recovery authority.
* Evaluation uses source revalidation, per-axis deadlines and resident lane ticket checks. It does not currently provide a durable task-lifecycle transition demonstrating T1 expiry followed by T2 acceptance, with T1's audit retained. This needs separate proof; a historical HTTP receipt is not a fresh GPU ticket.

`tests/test_i4a_lifecycle_blockers_dev.py` uses the original Owner, Physical ActionPort and canonical WAL with synthetic Native and resident HTTP. It runs S1's three settled Actions and T1's five-axis evaluation, then explicitly cancels S1 and releases the Intent through Owner methods. The next synthetic resident decision is still rejected by the Stage27 handoff, while the prior WAL and the other Self stay unchanged. Retaining a new Memory then independently shows the restored-snapshot restriction in Stage26. Cancellation in this fixture is an explicit synthetic test decision, not a model or autonomous approval. The test does not demonstrate T1 expiry or S2.

A safe implementation needs a source-qualified new current-Owner selection path, explicit reviewed lifecycle transition, an authenticated run boundary carried through issuer, loop and C evidence admission, independent identities and budgets, task expiry/receipt controls, and hostile tests including unresolved WAL and concurrent changes. The current negative test provides no basis for granting any new physical authority. I1 compatibility and integration require separate review at both branch HEADs.

Classification: `I4A_MULTI_SKILLRUN_HOLD`; DEV_ONLY / QUALIFICATION_NO_GO / SCIENCE_NOT_RUN. No real World, Gemma, C1 persistence or overall C PASS is claimed.
