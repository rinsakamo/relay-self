# B-NP1a Schema bootstrap (CPU/offline)

The fresh original resident runner accepts the explicit `--exploration-schema-dev` opt-in. Its default remains disabled and keeps `initial_patterns()` unchanged. The opt-in selects `initial_patterns_with_relative_move()` at original Owner creation. Immediately after original Resident construction and before bridge login, `bootstrap_fresh_schemas` registers independent per-Self `SchemaSnapshot`s at the Owner Registry revision. The `exploratory` v1 module is FULL only for the opt-in, otherwise OFF. FULL requires the exact innate `exploration-relative-move` v1 pattern. Schema activation is never inferred from pattern presence. This configuration provides no new Goal, Intent, physical Action or execution permission.

Existing checkpoint formats do not record Schema activation. A caller requesting Schema rebootstrap through the recovered-owner entry receives an explicit HOLD for either setting; the saved Registry and files are not replaced. Legacy recovery without that request remains available and has no registered Present Schema. Fresh bootstrap is restricted to owners created for that explicit fresh configuration. It is not checkpoint evidence and cannot authorize restored activation.

This gate does not start a Present consumer, generate Native/Paper links, integrate E SENSE, adopt Questions, perform inference, or access a real World. B-NP1b still needs normal Present invocation, fresh ordinary source updates and complete bridge logout/reJOIN proof; recovered Schema activation requires durable same-Self activation evidence and validation before rebootstrap can be enabled.
