# RelaySelf

Persistent cognition, present projection, and embodied control runtime for Relay.

RelaySelf is the self-side architecture of the Relay family. It separates what persists, what matters now, and what connects the self to an environment.

## Minimal basis

RelaySelf is organized around five architectural bases:

1. **Persistent Cognition** — cognitive state that persists across moments and sessions.
2. **Present Projection** — the currently active projection produced from persistent cognition and the current situation.
3. **Embodied Boundary** — the causal coupling surface through which the Self receives environment/body observations, regulates and interprets its embodied state, and hands authorized effect commands to external execution.
4. **Environment** — world state and dynamics outside the self, including any authoritative external body/world state and physical or simulated execution owned by the environment implementation.
5. **Authority / Provenance** — the rules and evidence that determine what may be believed, changed, authorized, or persisted.

The Environment is external to RelaySelf and connects through explicit contracts. Authority / Provenance is cross-cutting rather than a peer runtime subsystem.

RelaySelf may maintain a self-model, working self, capability model, body/resource estimate, belief, and appraisal about its embodiment. Those Self-side representations are not authoritative external body or world truth merely because they describe the Self's body or situation.

## Core invariants

- Persistent state is not present state.
- Observation and evidence are not belief.
- Self-side body/resource representation is not authoritative external body truth.
- Proposal, authorization, issuance/external execution, and consequence are distinct.
- Self and environment are distinct.
- Model output is not authority by itself.

## Status

RelaySelf is in early executable bootstrap. The current Python bootstrap implements Action Lifecycle, deterministic Action Supervision, Current Intent commitment with explicit reconsideration requests and decisions, and an independent Skill Execution lifecycle with explicit success, failure, and cancellation terminal classes.

The bootstrap now also includes a deliberately small durable Persistent Cognition slice: one `IdentitySpecification`, explicitly retained `Memory` values, and exact-scope `AppraisalDisposition` values can be written to and restored from a versioned local JSON snapshot. Each retained Memory and appraisal disposition preserves separate source provenance and integration provenance. Identity/SOUL seeding is explicit and keeps the appraisal disposition separate from `IdentitySpecification`; later exact-instance appraisal integration can override the corresponding class prior at Current-Appraisal projection time without implicitly rewriting class-wide state. Loading prior cognition does not convert it into fresh World attestation. Snapshot schema v2 writes appraisal dispositions and still accepts the prior v1 shape as an empty-disposition legacy snapshot; this remains a bounded compatibility path, not a general migration framework. Snapshot replacement is local/same-filesystem and fail-closed for malformed or unsupported schema data; this is not a general Memory database or active-lifecycle restart mechanism.

The bootstrap also exposes a minimal admitted decision-epoch coordinator. It services due `ActionSupervisor` deadlines first, then runs caller-owned deterministic/reprojection work, and invokes a supplied RelayEngine seam exactly once only when that work returns an unresolved cognition request. The coordinator does not classify raw events, own Present/Intent/Skill state, define a model request schema, own a clock, retry cognition, or constitute a deployed autonomous runtime driver.

The executable `RelayEngine` now owns two transient cognition request families under one replaceable provider boundary rather than owning model state. The existing bounded path is unchanged: a `BoundedChoiceRequest` carries finite admissible choices and provenance-bearing dynamic context, makes one `BOUNDED` call, and may make at most one explicit `THINK` escalation only when the bounded result is cognitively unresolved or inadmissible and the caller permits escalation. An optional request-carried identity input is a pure canonical projection of the existing durable `IdentitySpecification`; it is separate from dynamic Present/Memory context and does not become another SOUL owner. The target-local llama.cpp generated BOUNDED/THINK/OPEN renderers place that identity projection in one common leading system prefix before mode-specific rules while keeping `cache_prompt=false`. Jev/System One carries the same identity semantics explicitly in its state representation, but no cross-endpoint token/KV compatibility is claimed. Its result continues to record content-free cognitive-work facts and optional observational soft-wall-time comparison. An additive `OpenCognitionRequest` carries the same provenance-bearing dynamic context shape but no finite choices or THINK permission; `RelayEngine.open(...)` makes exactly one `OPEN` provider call and returns one transient expression with request identity, output provenance, elapsed work, and provider-reported call facts. Open output is presentation/cognition only: it does not establish World truth, mutate Current Intent or Skill state, persist Memory, authorize an Action, or prove external delivery. The target-local llama.cpp adapter keeps one provider owner while allowing an explicitly configured Jev-capable runtime to realize `BOUNDED` through `/v1/systemone`; `THINK` and `OPEN` remain chat-completions requests, and generated BOUNDED remains the supported path when System One is not configured. The adapter does not auto-discover Jev or silently fall back after a Jev provider failure. Matched physical evidence from #257 preserved the expected bounded choice on 24/24 calls in both generated and Jev arms with zero provider failures or wrong choices, while Jev reduced median provider latency by about 48.47% and emitted zero output tokens on that exact Gemma 4 12B Q4_K_M / RTX 3060 transaction. This earns Jev as the preferred BOUNDED realization for the tested Jev-capable local runtime class, not as a universal latency, quality, or calibration claim. Prompt/KV reuse remains unqualified and deferred to #259. Malformed envelopes, invalid bounded schemas, empty open expressions, and non-stop completions remain provider/protocol failures rather than cognitive uncertainty; the additive open path still has deterministic contract evidence rather than a separate live model-quality qualification.

The repository now also contains the first concrete Mineflayer adapter slice for the Minecraft MVP: a Node >=22 / Mineflayer 4.39.0 target-local JSONL bridge for offline/local connections, bounded control and food primitive effects, and provenance-bearing spawn/body/movement/death/respawn observations. Its Python decoder fails closed on version, session, sequence, and schema mismatches. This target-local adapter now has bounded live qualification evidence: #138 qualified the concrete supervised Mineflayer Action-to-movement path, and #141 exercised the same adapter inside the terminal Minecraft vertical including grounded EAT/FLEE consequences. This does not turn primitive acknowledgements into Skill success and does not claim pathfinding, authenticated-account support, general threat classification, or generic Minecraft World truth. Adapter-local admission now routes known primitive effect results and selected material body/session observations into the canonical decision-epoch coordinator while leaving ordinary high-frequency `move` updates outside high-level cognition by default. A Mineflayer `applied` or `rejected` effect result closes the primitive Action as a known `OUTCOME`; it still does not determine Skill success/failure. An adapter-local asynchronous process session can now launch one Node bridge, consume its startup attestation, exchange the same JSONL protocol, detect EOF explicitly, and shut it down without reconnect/retry semantics. Live local/offline Minecraft connectivity for the bounded qualified path is recorded; broader deployment environments remain outside the supported boundary. The target-local survival snapshot now also carries server time when available, inventory item facts, and bounded nearby entity facts without threat/appraisal labels; primitive food realization is split into explicit equip-item and consume-held Actions. A reusable live-qualification harness now exercises the canonical supervised Action-to-Mineflayer path and requires both an applied forward-control result and observed position change before reporting success; the repository now contains recorded successful live Minecraft qualification evidence for both the primitive adapter gate (#138) and the end-to-end terminal vertical (#141).

A read-only operator observability slice now deterministically reduces bounded Mineflayer/lifecycle histories into a compact Markdown activity summary. High-frequency `move` observations are collapsed into provenance-bearing movement spans, while existing Intent, Skill, Action, non-movement Mineflayer events, and optional before/after Persistent Cognition Memory deltas remain inspectable. The summary is presentation only and does not write cognition or create a trace owner.

An experiment-local controlled Minecraft vertical harness now composes current Mineflayer evidence, Current Intent, SkillExecution, Action Supervision, and RelayEngine into bounded WAIT/EAT/FLEE paths without adding a generic RuntimeDriver. EAT requires later observed food increase before Skill success; FLEE requires later observed progress toward the selected destination and always clears movement control through a separately supervised Action. A separate explicit integration transaction can now retain one observed successful FLEE result as provenance-bearing Memory, save/load the same Persistent Cognition identity, and supply that reloaded Memory as prior experience beside a later session's independently provenance-bearing Mineflayer evidence. Neither Skill success nor the human summary persists automatically. The bounded experiment-local #141 terminal composition runner uses vanilla Hunger mechanics, fresh Mineflayer consequence evidence, target-native heading semantics, and overall fail-closed evidence deadlines. A fresh exactly-once live run on the qualified main subject has now completed successfully: one Self performed situation-dependent WAIT/EAT/FLEE behavior, used the real RelayEngine without an LLM-per-tick loop, recovered from a mismatching consequence through Present reprojection, explicitly retained one grounded FLEE experience, terminated and restarted as the same Self, reloaded that Memory separately from fresh World evidence, and used it in a later grounded post-restart decision. The recorded terminal evidence qualifies this bounded RelaySelf 1.0 Homunculus MVP vertical; it does not imply a general autonomous Minecraft agent, general navigation, or a general runtime driver.

The supported Skill start seam derives its immutable `intent_id` association from the actual Current Intent owned by `IntentCommitment` instead of accepting an arbitrary caller-supplied intent identity. Snapshots derived from one supported Skill start root now share owner-local ephemeral lineage currentness: a successful transition makes predecessor snapshots stale, so an old `STARTED` snapshot cannot create another terminal branch or later seed a supported Action proposal.

The supported Action proposal seam requires the **current** snapshot of a `SkillExecution` in `STARTED` state plus the `IntentCommitment` owner, requires that the Skill's associated intent matches the actual Current Intent, and derives immutable `skill_execution_id` and `intent_id` associations rather than accepting those identities as caller text. Action lifecycle snapshots derived from one proposal root are likewise lineage-linear: after one successful transition, predecessor snapshots remain inspectable but cannot be advanced into alternate authorization, denial, issuance, or closure branches.

These guarantees are intentionally lineage-local. RelaySelf still does not have a repository-wide registry that proves global uniqueness or selects one globally latest root when independently created Skill or Action roots reuse the same textual identity. It also does not claim durable lineage retention across restart/serialization or concurrent/thread-safe lifecycle mutation.

The bootstrap does not yet declare a supported package-distribution boundary, minimum Python version, dependency floor, general autonomous runtime driver, general scheduler, general-purpose environment adapter beyond the qualified Mineflayer vertical, arbitration engine, reconsideration-trigger detector, general closed-loop Skill controller, global latest-Skill-execution registry, general external body/execution runtime beyond the qualified Minecraft slice, or general authority-policy engine. In particular, Action Supervision does not prove that a deployed clock or event loop will eventually deliver future decision epochs; Intent Commitment does not decide which runtime changes should request reconsideration or which candidate intent should win; and Skill Execution does not validate Skill capability existence or preconditions, generate primitive Actions, automatically cancel when its associated Current Intent later changes, or make local cancellation proof that a physical/controller process or child Action has stopped.

Hypotheses, simulation results, and implementation facts must remain distinguishable.
